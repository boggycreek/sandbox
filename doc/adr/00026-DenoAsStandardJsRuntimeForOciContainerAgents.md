# 00026. Deno as Standard JavaScript Runtime for OCI Container Agents

## Context
Agent containers require a JavaScript/TypeScript runtime for executing AI agent harnesses, running AI SDK tooling, and evaluating dynamic code generated by agents.

Historically, Node.js provided broad npm compatibility but lacked runtime-level security controls. Any script or prompt-injected tool call inherited unrestricted access to the container filesystem, environment variables, and network. Additionally, running TypeScript required separate transpilation dependencies (`tsc`, `tsx`), while npm directory sprawl (`node_modules`) bloated container layer storage.

## Decision (What)
Deno 2.x is adopted as the standard JavaScript and TypeScript runtime across the entire agent image hierarchy.

The architectural principles governing runtime integration are:
- **Runtime-Level Capability Sandboxing**: Tool runners and script execution utilize Deno's granular permission boundary (`--allow-*`), restricting network targets, environment variables, and filesystem access independently of the outer container perimeter. This provides critical defense-in-depth against prompt injection and malicious tool payloads.
- **Native TypeScript Execution**: TypeScript executes directly without intermediary transpile steps or build dependencies, simplifying agent toolchains and accelerating container cold-start times.
- **Persistent Package Caching**: Module resolution uses Deno's native npm compatibility layer, with packages cached on the persistent agent home volume (`DENO_DIR`), eliminating layer bloat and avoiding fragile `node_modules` trees across container recreations.
- **Decoupled Agent Harnesses**: Standard agent harnesses leverage Deno's global binary installation or native Go static binaries, ensuring the base container image remains minimal and predictable.

## Status
Accepted (Alpha as-built).

## Consequences
### Positive
- Runtime capability enforcement provides defense-in-depth against prompt injection attacks attempting unauthorized data exfiltration or host probing.
- Native TypeScript support eliminates auxiliary transpilation toolchains from container images.
- Caching on persistent home volumes prevents container layer bloat and speeds startup.
- Full npm ecosystem compatibility without requiring a separate Node.js installation.

### Negative / Trade-offs
- Native C++ Node.js add-ons with deep V8 internals binding are incompatible, requiring modern pure-JS, WASM, or CLI alternatives.
- Tool runners expecting direct `node` binary naming must invoke `deno` or use standard CLI wrappers.
